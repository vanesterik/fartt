# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Fartt (Financial Analysis Real Time Trading) is an MCP server that gives an agent the tools to analyse stocks on Euronext and US exchanges, with Claude Code as the analyst and the operator's interface. It's decision support for personal use: the agent combines many signals (market data, technical indicators, support/resistance, fundamentals, market context, charts) into a view, and a journal scores every call afterwards against a world index ETF. The server owns data, risk limits and state; the agent can read the limits but never change them. It's a solo research project, not production infra: expect research code (notebooks) and library code (`src/fartt`) at different levels of polish.

The plan is the PRD, `docs/product/stock-analysis-prd.md` (problem, users including the agent, the eight-step analysis procedure, tool surface, the three stages from paper trading to server-placed orders and their gates, the risk config, risks and open questions). It's delivered in epics on the board, in this order: **A** Data Foundation (#88), **B** Technical Analysis (#89), **C** Journal & Evaluation (#90), **D** Analysis Pipeline (#91; A–D are the walking skeleton, a full analysis on one ticker), then **E** Visualization (#92), **F** Market Context (#93), **G** Fundamentals & Screening (#94), **H** Trade Plan & Risk (#95), **I** Validation (#96), **J** Live Orders (#101). Stories are written just in time, one epic at a time. Epic designs live in `docs/specs/`, implementation plans in `docs/plans/`.

The project pivoted in place from BTC forecast trading. Code from that direction (the ccxt exchange layer, the forecast tools, the model pipeline and its notebooks) stays in the tree until the story that replaces or removes it lands, so the sections below still describe it; the epics and the PRD, not that code, say where the project is going.

The project follows the [cookiecutter data science](https://drivendata.github.io/cookiecutter-data-science/) layout: `notebooks/` for exploration, `docs/` for the PRD, designs and plans, `src/fartt` for library code, `tests/` for unit tests.

## Current state of the codebase (important)

**What exists and works:**

- **Market data.** The exchange layer (`fartt/exchange/`, ccxt behind an `Exchange` Protocol, Bitvavo by default) and the candle cache (`fartt/candle_cache.py`, one append-only CSV per market and interval under `assets/`). `fartt download` fills and updates a cache.
- **Stock data provider** (epic A, story A1). `fartt/data/` holds the `DataProvider` Protocol (`listing`, `history(ticker, start)`, `quote`), its `NamedTuple` types (`Candle` with a session `date`, `Dividend`, `Split`, `History`, `Listing`, `Quote`), its errors (`UnknownTicker`, `ProviderUnavailable`, `UnsupportedExchange`), `sessions.py` (ticker suffix to `exchange_calendars` code, `newest_closed_session` with a 30-minute `CLOSE_MARGIN`) and `YFinanceProvider`, the only module that imports yfinance. Prices are split-adjusted, not dividend-adjusted; dividends and splits come out as separate records. Nothing uses it yet: the stock cache (A2) and the server (A3) switch to it next.
- **The MCP server.** `fartt serve` runs it over stdio; Claude Code starts it from `.mcp.json`. It has four tools: `get_candles`, `get_forecast`, `analyze_forecast` and `get_model_info`. See Architecture below.
- **The model pipeline**, exercised from the notebooks `notebooks/2.0-kve-data-analysis-mlp.ipynb` and `notebooks/2.1-kve-data-analysis-cnn.ipynb`, not from the CLI or the server. `src/fartt/model/prepare_datasets.py::prepare_datasets` loads a market's cached CSV, sorts/deduplicates it by timestamp, computes the candle return (`calculate_candle_returns`: the signed percent change as a fraction, in the `Return` column), and builds sliding lag windows via its own `train_test_split` helper: a chronological, non-shuffled three-way split (60% train / 20% val / 20% test by default, via `train_size`/`val_size`; not to be confused with the removed sklearn-based module of the same name). Models are assembled by builders that satisfy the `ModelBuilder` Protocol (`src/fartt/model/builder.py`, a zero-arg `build() -> nn.Module`), each with its own typed pydantic config: `MLPBuilder`/`MLPConfig` (`num_layers` blocks of Linear→BatchNorm1d→ReLU→Dropout, sized by `hidden_features`) and `CNNBuilder`/`CNNConfig` (`num_layers` blocks of Conv1d→BatchNorm1d→ReLU→Dropout with `hidden_channels`/`kernel_size`, then global average pooling). Both configs share the field names `in_features` (the lag-window width passed as `num_lags` to `prepare_datasets`), `out_features` (default 1), `num_layers` and `dropout_rate`; the blocks live in `blocks.py` (`linear_block`/`conv_block`). `src/fartt/model/train_model.py::train_model` fits an untrained `model` in place with `nn.MSELoss`/Adam over minibatches for a fixed number of epochs. There's no cross-validation: 5-fold `TimeSeriesSplit` CV meant 6 training runs per model just to feed a diagnostic chart, so it was replaced with the fixed val split above. Passing `x_val`/`y_val` records a per-epoch train/val `loss_history` (empty if omitted); it returns `(model, loss_history)`. `src/fartt/model/evaluate_model.py::evaluate_model` reports directional accuracy (`calculate_accuracy`), RMSE and MAE on the train/test splits. `src/fartt/model/persist_model.py::save_model`/`load_model` checkpoint the whole `nn.Module` (architecture + weights, via `torch.save`/`torch.load`), so loading doesn't need the matching config or builder; `load_model` returns the model in eval mode. Neither notebook calls `persist_model` yet.
- **Backtesting helpers.** `fartt/features/calculate_candle_returns.py` (signed percent-change per candle) and `calculate_trade_returns.py` (a functional long-only backtest over a candle-return series, with cost/slippage/threshold/max-holding-period/stop-loss support and an optional `predicted_candle_returns` argument for backtesting a signal against realized price) replaced the older `TradeStrategy` class. `fartt/visualization/` has matching plotting helpers.

**What doesn't exist yet** (each is a later epic):

- Paper trading, the portfolio and the server-enforced risk limits (epic D), unattended operation (epic E) and live orders (epic F). No tool places orders yet, paper or live.
- The model to trade with (epic B). The MLP and CNN are the first of five candidate architectures to screen (GRU, a fresh N-BEATS and a time-series transformer are still to build), alongside zero-shot foundation models and naive baselines; only models that beat the baselines go on to a walk-forward backtest after costs. N-BEATS was tried once before (`NBeatsNet`, `nbeats_config.py`, beta-NLL loss, a confidence output) and deleted: a 130-run reproducibility check found beta-NLL didn't reliably fix its confidence calibration (r ≈ −0.09 under every configuration). References to `NBeatsNet`/`nbeats_config`/`beta_nll_loss`/`confidence_calibration.py` in git history predate that deletion.
- Device selection: `fartt/model/device.py::get_device()` exists but nothing imports it, so training always runs on CPU.

`uv run pytest` collects and passes cleanly; don't assume the suite is broken.

## Commands

The everyday commands are tasks in `Taskfile.yml`; `task --list` names them. `task setup` installs the project from `uv.lock` and wires up the git hooks, and `task check` (lint + typecheck + test) is the same command the pre-push hook runs, so the two cannot drift apart. `task` comes from the global `mise` setup (`mise use -g aqua:go-task/task`); it cannot install itself, so it is the one prerequisite `task setup` does not cover.

```bash
task setup                       # uv sync + install the lefthook hooks
task check                       # lint + typecheck + test, as the pre-push gate runs them
task lint                        # ruff format --check + ruff check, without writing
task format                      # ruff format + ruff check --fix
task typecheck                   # pyright (strict mode, src/ only — tests/ excluded)
task test                        # pytest, offline
task test:network                # live exchange tests + the end-to-end check of fartt serve over stdio (deselected by default)
task pre-commit                  # the pre-commit hook's checks over staged files
task outdated                    # direct dependencies with a newer release
```

Tool versions are upgraded on purpose, never because a run nags: ruff's rule set is pinned in `pyproject.toml`, and pyright's new-release warning is silenced. Instead, Dependabot (`.github/dependabot.yml`) opens weekly pull requests for newer releases: minor and patch updates grouped into one for dev tools and one for runtime dependencies, each major update on its own. There's no CI, so check a Dependabot pull request out and run `task check` (or push to it) before merging. `task outdated` is the on-demand version.

Everything below remains the direct route, and is what the Taskfile calls. Dependency management is via `uv` (see `uv.lock`), run from the repository root. The Python version is pinned in `.python-version` (3.14) and matched by `requires-python` in `pyproject.toml`; Dependabot doesn't track it, so moving to a new Python release is a deliberate change to both.

```bash
uv sync                          # install dependencies
uv run fartt download             # download candle data (see arguments below)
uv run fartt serve                # run the MCP server over stdio (Claude Code starts it from .mcp.json)
uv run pytest                    # run test suite
uv run pytest tests/model/test_train_model.py::test_train_model_reduces_loss  # single test
uv run pytest -m network         # run the live exchange tests (deselected by default)
uv run ruff format .             # format
uv run ruff check . --fix        # lint
uv run pyright                   # type check (strict mode, src/ only — tests/ excluded)
```

`fartt download --ticker TICKER [--assets-dir DIR]` (default `assets`) fills or updates one ticker's stock cache through `YFinanceProvider` and `StockCache`. Tickers use Yahoo's format (`AAPL`, `ASML.AS`, case and surrounding spaces don't matter). An unknown ticker or a suffix outside the universe exits with code 2; an unreachable provider exits with code 1 and leaves the cache unchanged. The CLI is plain `argparse` (`fartt/cli.py`: `build_parser()` and `main(argv)`); the agent never calls it, it calls the MCP server's tools.

`fartt serve` takes the same four options (`--interval` defaults to `1h`), plus the analysis settings `--fee` (0.0025 per leg), `--slippage` (0.001 per leg), `--threshold` (default the round-trip cost, `2 * (fee + slippage)`) and `--hit-rate-window` (100 candles). All but the window are fractions; nonsense values (negative, `nan`, `inf`, a window below 1) exit with code 2, and a threshold below the round-trip cost logs a startup warning. It runs the MCP server (`fartt/server/server.py`) over stdio. Claude Code starts it from the project's `.mcp.json`; the agent calls its `get_candles`, `get_forecast`, `analyze_forecast` and `get_model_info` tools. Both commands reject an unknown exchange, an interval the exchange doesn't offer or an unknown market with exit code 2; an unreachable exchange stops `download` with exit code 1, while `serve` starts anyway and serves cached candles flagged as stale.

`tests/e2e/test_server_stdio.py` checks the server end to end: it starts `fartt serve` from `.mcp.json`'s command (with a temporary `--assets-dir` and `--interval 1d`), runs the trading cycle's tools in order, and asserts stdout carries only JSON-RPC, including anything written at shutdown. Each new tool joins it: add its name to `EXPECTED_TOOLS` and its call to the cycle test.

There is no `fartt train` CLI command — it was removed, and the train/evaluate pipeline (`prepare_datasets` → `MLPBuilder`/`CNNBuilder` → `train_model` → `evaluate_model`) is currently only exercised from `notebooks/2.0-kve-data-analysis-mlp.ipynb` and `notebooks/2.1-kve-data-analysis-cnn.ipynb`, not wired into any CLI entrypoint. Each notebook loads the cached CSV for a market/interval, sorts/deduplicates it, computes the candle return (`Return`), builds sliding lag windows via a chronological 60/20/20 train/val/test split (`train_size`/`val_size` on `prepare_datasets`), builds its model (`MLPBuilder(config).build()` or `CNNBuilder(config).build()`), fits it with `train_model` — a single fit against the validation split, no cross-validation (see "Current state" above) — and logs directional accuracy/RMSE/MAE via `evaluate_model`. Neither notebook calls `persist_model`, so no checkpoint is saved from this path currently.

Hooks are managed by `lefthook` (`.lefthook.yml`) and stand in for CI, which this project doesn't have. On every commit, notebooks get their outputs stripped, staged Python files get `ruff format` + `ruff check --fix`, then `pyright` and `pytest` run. On every push, `task check` runs the full suite on the whole repository (`ruff format --check .`, `ruff check .`, `pyright`, `pytest`), because pre-commit only sees staged files and a commit touching only `pyproject.toml`, `uv.lock` or `.mcp.json` would otherwise skip tests and type checks. `git push --no-verify` skips the gate for one push; use it deliberately, never by default. Tests marked `network` call a live exchange and are deselected by default; run them with `task test:network`.

## Architecture

- **`fartt/cli.py`** — `argparse` entrypoint (`fartt` console script, `main(argv)`; `build_parser()` defines the subcommands). Loguru is configured in `main()` (stderr + rotating `logs/cli.log`), not at import. No shared config object. `download` updates one ticker through `StockCache(YFinanceProvider(), assets_dir)` and logs the result (new candles, a rebuild and its reason, or already up to date). `serve` still validates its exchange, market and interval through `_open_cache` and runs `build_server(cache, market, interval)` over stdio until A3 (#99) moves it to the stock cache.
- **`fartt/candle_cache.py`** — `CandleCache`: one market and interval's candles as an append-only CSV under `assets_dir`, kept up to date through the `Exchange` interface (`fartt/exchange/`). It pages through closed candles from the last cached one, skips gaps in the exchange's history, and replaces only its own last line when the exchange amended that candle. `fartt download` and the MCP server both use it.
- **`fartt/stock_cache.py`** — `StockCache(provider, assets_dir, clock)`: each ticker's split-adjusted daily candles (`candles.csv`), dividends and splits (`events.csv`) and listing (`listing.json`) under `assets_dir/stocks/<TICKER>/`. `update(ticker) -> UpdateResult(new_candles, rebuilt, fetched)`: a first update fetches the full history; later ones re-fetch from the last cached session and append what's newer; a split after it, or any change to the last cached candle's prices (volume aside), rebuilds the whole history (files swapped in with `os.replace`); a cache already holding the newest closed session doesn't call the provider. A torn last line is healed first. Reads (`latest`, `events`, `listing`) take a shared `fcntl` lock on the directory's `.lock`, updates an exclusive one.
- **`fartt/data/`** — the stock data layer replacing `fartt/exchange/` (which goes in A3). `DataProvider` takes tickers in Yahoo's format (`AAPL`, `ASML.AS`); `calendar_for` maps the suffix to an exchange calendar and rejects suffixes outside the universe with `UnsupportedExchange`. `YFinanceProvider(ticker_factory, clock)` returns closed sessions only, maps yfinance's missing-ticker errors and Yahoo's HTTP 404 to `UnknownTicker` and everything else to `ProviderUnavailable`, and turns a bid/ask of 0 into `None`. It sets `yfinance.config.debug.hide_exceptions = False` (the per-call `raise_errors` is deprecated). yfinance and exchange_calendars have minimal stubs under `typings/`.
- **`fartt/exchange/`** — the `Exchange` Protocol (`has_market`, `supported_intervals`, `fetch_closed_candles`), the `Candle` NamedTuple, `ExchangeUnavailable` (what the layer raises when the exchange can't answer, so callers never see ccxt's exceptions), and `CcxtExchange`, the only module that imports ccxt (default exchange `bitvavo`).
- **`fartt/forecast/`** — the `Forecaster` Protocol (read-only `name`, `kind`, `required_candles`, `trained_through_ms`, plus `predict(candles) -> float`, the next candle's expected return as a fraction), the frozen `Forecast` (`model`, `expected_return`, `based_on_ms`, `applies_to_ms`), `NotEnoughCandles`, and `forecast()`, which wraps `predict` with timestamps. `RepeatLastReturn` is the naive baseline that epic B's trained model has to beat and will sit beside. `analysis.py` holds `Settings` (with `round_trip_cost`), `Analysis` and `analyze()`: the forecast after costs, entry (`> threshold`) and exit (`< -threshold`) flags using `calculate_trade_returns`' rules, and a directional hit rate over the last `hit_rate_window` candles that scores only candles after `trained_through_ms` and skips exact zeros.
- **`fartt/server/`** — `build_server(cache, market, interval, forecaster, settings)` returns the MCP SDK v2 `MCPServer`; `fartt serve` passes `RepeatLastReturn()` as the forecaster. It has four tools. `get_candles(count=1..200)` updates the `CandleCache` and returns the newest closed candles as structured output (`market`, `interval`, `columns`, `rows` as `[time, open, high, low, close, volume]` arrays, `new_candles`, `is_current`, `warning`). The 200 maximum keeps the result well under Claude Code's MCP output limit (about 25k tokens). An unreachable exchange (`ExchangeUnavailable`) degrades to cached candles with `is_current: false` and a warning, or a `ToolError` when nothing is cached; any failure retrying can't fix (a market the exchange doesn't list, a cache file it can't write) is a `ToolError` telling the agent the operator must act. `get_forecast()` reads `forecaster.required_candles` candles from the cache (never the exchange) and returns `model`, `expected_return` (a fraction), `applies_to` and `based_on` (candle open times), `is_current` and `warning`; too little history is a `ToolError` with the exact `fartt download` command. `analyze_forecast()` returns the same timing fields plus `expected_return`, `round_trip_cost`, `expected_return_after_costs`, `threshold`, `clears_entry_threshold`, `clears_exit_threshold`, `hit_rate` and `hit_rate_candles`, and shares `get_forecast`'s cache read, errors and staleness check. `get_model_info()` returns `name`, `kind`, `required_candles`, `trained_through` (the training data's cutoff, from `trained_through_ms`), `trained_at` and `metrics` (both `null` until epic B adds them to the Protocol), a `note`, `newest_cached`, `newest_closed` and `is_current`; it answers even with an empty cache.
- **`fartt/features/`** — feature engineering over Polars DataFrames: `calculate_technical_indicators.py` computes Bollinger Bands / EMA / MACD / RSI via `talib`, configured through `technical_indicators_config.py`; `calculate_candle_returns.py` computes signed percent-change per candle; `calculate_trade_returns.py` is a functional long-only backtest over a candle-return series (cost/slippage/threshold/max-holding-period/stop-loss, with an optional `predicted_candle_returns` arg to backtest a signal known one tick ahead against realized price) — this replaced the older `trade_strategy.py::TradeStrategy` class.
- **`fartt/constants.py`** — centralized string labels (column names, indicator labels) and a small colour palette, shared across the cache, features and visualization code to avoid stringly-typed column name drift between DataFrame producers and consumers.
- **`fartt/model/`** — the regression pipeline epic B (Model Selection) builds on. `prepare_datasets.py::prepare_datasets` loads a market's cached CSV, sorts/deduplicates it, computes the candle return (`Return`), and builds sliding lag windows via its own `train_test_split` helper (non-shuffled, chronological 60/20/20 train/val/test split). `builder.py::ModelBuilder` is the Protocol every architecture's builder satisfies (`build() -> nn.Module`); `mlp_builder.py`/`mlp_config.py` and `cnn_builder.py`/`cnn_config.py` implement it for the MLP and CNN, assembled from the reusable `linear_block`/`conv_block` in `blocks.py`, with configs sharing the field names `in_features`/`out_features`/`num_layers`/`dropout_rate` (`hidden_features` for the MLP, `hidden_channels`/`kernel_size` for the CNN). `train_model.py::train_model` fits an untrained model in place with `nn.MSELoss`/Adam over minibatches (`init_dataloader`/`init_optimizer`) — a single fit, no cross-validation; an optional `x_val`/`y_val` pair is recorded as a per-epoch `loss_history` for the learning-curve diagnostic instead. `evaluate_model.py::evaluate_model` reports directional accuracy, RMSE and MAE on the train/test splits. `persist_model.py` saves/loads the whole trained module via `torch.save`/`torch.load` (`load_model` returns the model directly, in eval mode). This replaced an earlier hand-rolled N-BEATS prototype (see "Current state" above).
- **`fartt/visualization/`** — Matplotlib/seaborn plotting helpers, mostly for notebook use. `candlestick_chart.py` (Bollinger/EMA/MACD/RSI overlays via `mplfinance`) and `missing_value_heatmap.py` predate the move from classification to regression; `candle_returns.py`, `trade_returns.py`, `diverging_bar_chart.py` (a shared bar-color-by-sign helper the last two build on), and `evaluation_line_chart.py` (a train/test/predicted line chart for evaluating a trained model, with an optional `y_train`) support it. `plot_styles.py::apply_plot_styles` sets shared tradingview-style `rcParams`.
